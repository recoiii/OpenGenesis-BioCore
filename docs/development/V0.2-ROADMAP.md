# OpenGenesis-BioCore v0.2 Roadmap

## Theme

**Platform Maturation & Production Readiness**

v0.2 is a bridge between the frozen v0.1.0 platform and the broader production-NGS work planned for v0.3. It should strengthen operational reliability, compatibility, diagnostics, file integrity, export/report foundations and validation discipline without turning into a second feature-accumulation release.

## Baseline

The technical frozen baseline is OpenGenesis-BioCore v0.1.0 Iteration 044:

- source candidate: `OpenGenesis-BioCore-iteration-044-source-CANDIDATE.zip`;
- SHA-256: `ba2406131266641bdaf9516b416fa0ca868a6ba4eb12d58c6b31494e491c94ae`;
- Linux matrix: GCC Debug 67/67, GCC Release 67/67, Clang Debug 67/67, GCC ASan+UBSan 67/67;
- native Windows closure: MSVC Debug 67/67 and MSVC Release 67/67;
- project schema: v6;
- Worker Protocol: v2.

The public GitHub `main` branch contains three post-release citation/DOI metadata commits after the v0.1.0 source release. Those changes do not modify runtime source and are intentionally retained in the v0.2 branch.

## Validation policy

Every iteration follows the same gate:

1. implement a narrow, reviewable change;
2. build and run the required regression matrix;
3. generate the exact Gemini review package as 3 or 4 Markdown parts;
4. obtain an independent Gemini verdict;
5. freeze only on `ACCEPT`.

A blocking finding means `REJECT`/revision and the same iteration remains open. There is no `ACCEPT WITH CHANGES` state for freezing.

## Compatibility boundary

Until an iteration explicitly declares and validates a migration, v0.2 must preserve:

- existing `org.biocore.*` plugin and pipeline identifiers;
- `.biocore` / `share/biocore` paths;
- `X-BioCore-*` compatibility headers;
- established `BioCore...` VCF machine identifiers;
- Worker Protocol v2;
- project schema v6;
- existing v0.1 project data and immutable execution-plan semantics.

Human-facing branding remains `OpenGenesis-BioCore`.
